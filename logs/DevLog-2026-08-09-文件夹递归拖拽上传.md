## 一、概述

上传面板现在支持直接拖入或选择整个文件夹，并递归识别 PDF、TXT、Markdown 和 DOCX。浏览器端会把不支持格式、系统文件、不安全路径和重复相对路径列入 ignored 清单，其余有效文件继续上传；服务端仍逐项执行可信边界校验，不依赖前端过滤。

同名冲突按工程身份模型处理：普通单文件上传继续以文件名为逻辑身份；文件夹上传以 NFC 规范化的相对路径为逻辑身份。因此 `project/backend/README.md` 与 `project/frontend/README.md` 是两个独立文档，重新上传同一相对路径才表示替换原逻辑文档。

为避免大目录阻塞页面或瞬时压垮 embedding/Qdrant，目录扫描使用异步浏览器 API，前端每 20 个文件顺序提交一批，后端把磁盘写入、内容检查和同步摄取放到工作线程中执行。

## 三、API 设计

### `POST /documents/upload-batch`

旧客户端仍可只发送多个 `files`。文件夹客户端为每个文件额外发送一个同序字段：

```text
files=<binary README.md>
relative_paths=project/backend/README.md
files=<binary README.md>
relative_paths=project/frontend/README.md
```

如果提供 `relative_paths`，其数量必须与 `files` 完全一致，否则整个请求返回 400。路径本身的错误属于单文件错误，记录到 `results[]` 后继续处理后续文件。

后端响应中的 `filename` 和 `source` 使用逻辑相对路径；服务端 UUID 存储路径不对外暴露。

## 四、实现细节

### 4.1 异步目录扫描

拖拽优先调用 `DataTransferItem.getAsFileSystemHandle()`，使用异步迭代器递归读取目录；不支持或授权失败时回退到 `webkitGetAsEntry()`。WebKit `readEntries()` 可能分多批返回，因此循环读取到空批次为止，不能只调用一次。

选择文件夹使用 `<input webkitdirectory>` 提供的 `webkitRelativePath`。扫描期间 UI 显示状态并禁用重复扫描/上传操作。

### 4.2 过滤与失败隔离

前端接受 `.pdf`、`.txt`、`.md`、`.markdown`、`.docx`，忽略 `.DS_Store`、`Thumbs.db`、`desktop.ini`、其他扩展名和重复相对路径。ignored 文件可见但不会加入 multipart。

后端重新检查扩展名、大小、PDF magic、DOCX zip 结构和 UTF-8；某个文件路径或内容非法时只返回该文件的 `status=error`，不会中止整批。

### 4.3 同名与身份

上传 identity 为 `upload:<normalized source>`，再与 collection 一起生成稳定 `document_id`。文件夹 source 是完整相对路径，因此不同目录同名不冲突；同一相对路径重传会进入现有版本化替换流程。

普通文件选择受浏览器隐私模型限制，只能得到 basename，因此两个来自不同本地目录但同名的独立选择无法可靠区分。前端会把第二个同名 basename 视为重复；需要保留二者时应选择或拖入包含它们的共同文件夹。

### 4.4 路径安全

相对路径先进行 Unicode NFC 和斜杠规范化，并拒绝空值、NUL、绝对路径、`.`/`..`、空段、Windows 驱动器前缀、超长段、过深/过长路径。末段必须与 multipart 文件名一致，避免路径清单与实际文件错配。

该路径从不参与磁盘目标拼接。上传字节始终写入 `data/raw/<uuid>.<ext>`，清理函数也只允许删除 `data/raw` 内的精确文件。

### 4.5 背压和事件循环

- 浏览器目录枚举使用异步 API，不在主线程同步遍历整个树；
- 前端固定每 20 个文件组成一个 multipart，并逐批 `await`，没有对所有文件执行 `Promise.all`；
- 后端逐文件处理，上传读取保持异步；同步磁盘写入、内容校验和摄取通过 `asyncio.to_thread` 移出事件循环；
- 当前策略优先保护单机 embedding/Qdrant，不追求无界上传并发。

## 七、边界情况与回退

- 不支持格式只忽略，不影响同目录中的有效文件；扩展名允许但内容损坏时由服务端逐项报错。
- 两个不同相对路径的同名文件独立；完全相同的相对路径只保留一份。
- 普通文件选择没有父目录信息，同名 basename 会冲突；选择共同文件夹可保留相对路径。
- `relative_paths` 是可选字段，旧客户端不需要同步升级。
- 浏览器不支持现代 File System Access API 时自动使用 WebKit entry；两者都不可用时仍可上传普通文件。
- 网络批次失败时停止后续批次，并保留此前批次的可见结果，避免误报全部失败。
- 当前不提供自动重试和并行上传；需要时应在实测 embedding/Qdrant 吞吐后增加有界并发，而不是无界并发。

## 八、影响分析

- **API 影响**：向后兼容；批量端点新增可选 multipart 字段，响应结构不变。
- **身份影响**：新文件夹上传用相对路径区分同名文档；普通单文件上传语义不变。
- **存储影响**：无新表和依赖；文件仍为 UUID 存储，Qdrant/SQLite 记录完整逻辑 source。
- **性能影响**：目录读取不阻塞 UI，上传批次和后端工作线程形成基础背压；整体仍按单机负载设计。
- **安全影响**：前后端双层过滤，服务端路径清单不参与实际文件系统寻址。
- **运维影响**：无需迁移旧数据；用户可直接用新面板上传文件夹验证新的 Hybrid collection。
