## 三、实现细节

### 数据模型

```sql
conversations: id | title | created_at | updated_at
messages:      id | conversation_id | role | content | sources(routing JSON) | created_at
```

- title 取自第一条用户消息（截断 60 字符）
- sources 以 JSON 存储，含 file_name / score 等
- routing 记录回答类型（rag / direct / greeting）

### 保存时机

非阻塞 daemon 线程在以下位置触发：

| 路径 | 触发点 |
|------|--------|
| `query_rag()` (同步 RAG) | 返回 response 之前 |
| `query_rag()` (同步非 RAG) | 返回 response 之前 |
| `query_rag_stream()` (流式 RAG) | yield done 事件之后 |
| `query_rag_stream()` (流式非 RAG) | yield done 事件之后 |

使用 `_save_exchange_safe()` 包装，所有异常被捕获 + 日志记录，不影响 API 响应。

### 前端交互

- 页面加载 → `GET /conversations` → 侧边栏列表
- 点击对话 → `GET /conversations/{id}` → 替换当前 messages
- 发新消息 → 流式完成后 `loadConversationList()` 刷新列表
- "New Chat" → 清空 messages，重置 conversationId
- 删除 → `DELETE /conversations/{id}` → 从列表移除，若为当前对话则切到 New Chat
- 删除按钮 hover 时才显示（opacity: 0 → 1），避免视觉杂乱

### 边界情况

| 场景 | 处理 |
|------|------|
| 后端重启 | SQLite 数据持久，重启后列表完整 |
| 空对话列表 | 显示 "No conversations yet" |
| LLM 保存失败 | catch + log，不影响 API 响应 |
| 长时间标题 | CSS text-overflow: ellipsis |
| 快速双击对话 | loadingConversation 防抖 |
| 删除当前对话 | 自动切到 New Chat |
| 无 conversation_id | 后端自动生成 12 位 hex UUID |
