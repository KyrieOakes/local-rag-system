## 一、概述

本轮从“面试时能否解释清楚、追问时实现是否站得住”出发，对项目做了一次全链路审计和整改。重点不是堆叠新功能，而是修复原实现中可能导致数据丢失、评测结论失真、事件循环阻塞、同名文档误删、半截回答落库和配置泄漏的工程缺口。

最终形成以下闭环：

1. 摄入从单纯 MD5 跳过升级为稳定文档 ID、管线指纹、版本化 point、原子激活和 durable cleanup queue；
2. 文档上传、Qdrant metadata、SQLite 注册表、本地 UUID 文件和前端删除使用同一身份链路；
3. Rerank 保留真实向量分数，Cross-Encoder 与 Hybrid 的失败回退可解释；
4. Retrieval 评测改用独立 evidence label 语义，旧报告不再与新报告混比；
5. SSE 的阻塞阶段移出事件循环，失败和取消不会保存半截回答；
6. 增加请求鉴权、CORS allowlist、readiness、上传内容校验、并发日志和可重复部署配置；
7. README、架构/API 文档、项目进度和校招复习材料全部按当前实现重写。

## 三、API 设计

### `GET /health`

仅表示 FastAPI 进程存活，不检查外部依赖，适合作为 liveness probe。

### `GET /health/ready`

检查 Qdrant、LLM `/models` 和 Embedding `/models`。全部可用返回 200；任一失败返回 503；每项 `status` 为 `ok` 或 `unavailable`，失败时只附异常类型字段，不泄漏 API key。

### `POST /documents/upload`

- 上传采用分块读取，不把整个文件一次性读入内存；
- 默认上限 25 MiB，超限返回 413；
- 扩展名与实际内容不符返回 400；
- 摄入和 embedding 在工作线程执行，不阻塞 FastAPI 事件循环；
- 任一阶段失败会清理本次临时文件；
- 成功响应返回原始 source、稳定 ID、状态和 chunk 数，不暴露服务端 UUID 路径。

### `GET /documents`

优先按 `metadata.document_id` 聚合并返回稳定 ID、原始文件名、类型和 chunk 数；旧 point 缺少新 metadata 时保留兼容聚合。

### `DELETE /documents/{identifier}`

1. 优先把 identifier 解释为稳定 `document_id`；
2. 旧客户端仍可传唯一 source；
3. 同名 source 对应多个文档时返回 409 和候选 ID；
4. 成功后精确删除 Qdrant points、注册表记录和受控目录内的 UUID 本地文件。

### `POST /rag/query/stream`

主要事件序列：

```text
routing -> status* -> token* -> sources -> done
```

失败时：

```text
[routing] -> [status*] -> error -> done
```

`error` 只暴露安全阶段码和用户可读消息；断连取消或中途失败不会把半截 assistant 消息写入 SQLite。

### 可选 API Key

当 `APP_API_KEY` 非空时，除 `/`、`/health` 和 `/health/ready` 外的 API 都要求 `X-API-Key`。空值保持可信单用户本地模式兼容。

## 四、实现细节

### 4.1 版本化摄入与失败补偿

逻辑文档身份按 collection 隔离。`document_id` 在同一路径/上传记录上稳定；`version_id` 由内容 MD5 和 pipeline fingerprint 共同决定。fingerprint 覆盖 loader/splitter、chunk size/overlap、embedding endpoint/model/revision 等影响向量结果的配置。

Point ID 使用 UUID5，由 `document_id + version_id + chunk_index` 确定。相同版本重跑是幂等 upsert，不同版本不会互相覆盖。

更新顺序为：

```text
写入新 Qdrant version
-> SQLite 原子激活 active row + enqueue predecessor cleanup
-> 幂等清理旧 version
-> complete cleanup record
```

新版本写入或 SQLite 激活失败时，只精确删除本轮 version，旧版本仍可检索。激活成功但清旧失败时，不回滚新版；任务保留在 SQLite 并在后续摄入中幂等重试，API 用 `cleanup_pending` 暴露状态。旧 UUID 上传还会按原始 source/path 归并到新的 original-filename identity，同名 legacy 文档获得可精确删除的 path-scoped ID。目录批量摄入会对账注册表：仅删除本次 input root 下已消失的文件，越界路径拒绝清理。

Qdrant 和 SQLite 并非同一分布式事务，因此进程在极窄的阶段边界被强杀时仍可能需要一致性巡检；文档没有被包装成不存在的 ACID 保证。

### 4.2 检索、Rerank 与分数语义

向量召回结果先转为 `RerankCandidate(document, vector_score)`，不再把距离分数隐式塞入可能缺失的 metadata。

- `none`：按原始向量分数返回；
- `cross_encoder`：对 query-document pair 重新打分；模型加载或输出长度异常时退回 vector-only；
- `hybrid`：融合向量名次和词法匹配；英文使用 token，中文增加 bigram，避免整段中文被当成一个 token。

`TOP_K` 控制无 Rerank 最终条数；启用 Rerank 时先召回 `RERANKER_CANDIDATE_TOP_N`，再保留 `RERANKER_FINAL_TOP_K`。同步和 SSE 使用相同规则。

### 4.3 evidence-label-v2 评测

旧 evaluator 可能只把“能够映射到实际 chunk 的标注”放进 Recall 分母，导致漏标/未命中 evidence 被静默排除。新语义先为每条 golden source/snippet 建立稳定 evidence label，再独立判断检索结果命中了哪些 label：

- 未命中 label 仍计入 Recall 分母；
- MRR 使用第一个相关检索结果的真实 rank；
- NDCG 使用 label relevance 和真实排序；
- 报告写入语义版本、dataset SHA-256、Git SHA/dirty、settings snapshot 和 pipeline fingerprint。

Notebook 只比较 `metric_semantics_version=evidence-label-v2` 且 dataset、mode、top-k、pipeline fingerprint 一致的报告，避免把不同数据和执行模式的数字放在同一排名中。LIVE 会真实执行并记录 Rerank attempted/applied/fallback；DEMO 明确禁用 Rerank 并使用稳定 SHA-256 种子。主指标只把前 `TOP_K` 交给 evaluator，额外候选仅供敏感度分析，确保 MRR 与 CLI 口径一致。

### 4.4 SSE 与后台副作用

路由、Qdrant 检索、Cross-Encoder 和同步存储操作使用 `asyncio.to_thread` 移出事件循环。RAG 生成使用模型原生异步 token 流；Direct answer 已在统一路由调用中一次性生成，因此按固定 Unicode 字符片段发送 SSE，保留中文、换行和连续空格，不再使用会破坏原文的 `.split()`。这避免了 Direct 路径为“原生流式”额外调用一次模型，但它不降低统一路由调用自身的首包等待。

查询日志、摘要和会话保存由固定 worker 的有界 executor 承担。队列满时明确拒绝并记录，不无限创建线程。`turn_id` 为一次 user/assistant exchange 提供幂等键；客户端重试时复用同一个 `X-Request-ID`/`turn_id`，才不会重复落库。

### 4.5 上下文与 Prompt 边界

长期上下文继续采用“服务端完整消息 + 滚动摘要 + 近期原文”：

```text
system + question + history + documents + reserved_output + safety_margin
<= model_context_window
```

预算不足时先确定性裁剪更旧历史和低优先级文档；连最低输入都无法容纳则同步接口返回 413，SSE 返回 context 阶段 error。Prompt 将 conversation memory 和 retrieved context 标记为不可信数据，禁止其中内容覆盖系统规则。

### 4.6 安全与部署

- 密钥只来自忽略的 `.env` 或进程环境；
- CORS 改为 allowlist；
- CORS 保持在鉴权外层，API Key 的早期 401 也带正确跨域响应头；
- 可选共享 API key 使用常量时间比较；
- request ID 用于日志关联；
- Docker Compose 的容器模型地址使用 `host.docker.internal`，避免错误指向容器自己的 localhost；
- 后端非 root 运行，前端由 Nginx 提供静态文件和基础安全响应头；
- CI 固定 Python 3.11、Node 22，并执行后端测试、前端 lint/build。

| 扩展名伪装 | 400，不进入 loader/embedding |
| 内容没变但切分或 embedding 配置变了 | fingerprint 改变，生成新 version |
| 新版本 embedding/upsert 失败 | 清理新 version，旧 version 保留 |
| SQLite 激活新版本失败 | 精确回滚新 Qdrant version，旧 registry/version 保留 |
| 激活后旧版本清理失败 | 新版本保持 active，durable cleanup queue 保留任务，响应标记 `cleanup_pending` |
| embedding 数量或维度不一致 | 拒绝写入，避免污染 collection |
| 批量目录中的文件被移除 | 仅清理 input root 内注册文档 |
| 旧 UUID 上传或 legacy 同名文档 | 归并到原文件名身份；为 legacy 记录生成路径作用域 ID，歧义 source 删除返回 409 |
| Reranker 加载失败 | 退回真实 vector score 排序 |
| 路由 JSON 损坏或模型异常 | fail-open 到 RAG，不凭猜测直答 |
| SSE 路由/检索/Rerank/生成失败 | `error + done`，内部细节脱敏 |
| SSE 客户端断开 | 取消生成，不保存半截回答 |
| SQLite 短暂锁竞争 | busy timeout + WAL + 条带锁 |
| 复用同一 `turn_id` 保存同一轮 | 幂等，不重复插入 |
| 后台队列满 | 明确拒绝副作用并记录，主答案不被无限线程拖垮 |
| 上下文超预算 | 确定性压缩/裁剪；仍放不下则 413/context error |
| 旧评测报告 | 保留历史，但不参与新语义策略比较 |

## 八、日志影响

`logs/history/rag_queries.jsonl` 继续保存完整查询追踪，本轮新增/收敛：

- conversation ID，以及作为 `turn_id` 记录的 request ID；
- routing、intent、检索和 Rerank 结果；
- 各阶段耗时；
- JSONL 进程内写锁，避免并发行互相穿插；
- 失败日志保留服务端 traceback，但对 HTTP/SSE 客户端只返回安全错误。

后台队列满、readiness 失败、版本补偿和越界文件清理拒绝也会写入 Python 日志。

## 九、与现有系统的影响

- **API 兼容**：既有上传、查询、SSE、会话和文档路由保留；文档删除仍兼容唯一 source。
- **更严格的输入**：伪装文件、超大文件、非法 conversation ID 和过长 history 会更早被拒绝。
- **评测口径不兼容**：旧 retrieval 报告不能与 `evidence-label-v2` 直接横向比较，必须重跑 baseline。
- **摄入配置变化会触发重建**：chunk/embedding 配置进入 fingerprint，避免错误跳过，但会产生真实重新 embedding 成本。
- **Rerank 配置收敛**：候选数和最终 top-k 现在真正生效，可能改变过去依赖硬编码值的结果。
- **安全默认仍适合本地**：`APP_API_KEY` 默认为空；部署到共享网络前必须显式设置 key，并进一步增加账户、租户和 RBAC。
- **单机边界保持诚实**：SQLite、本地文件、进程内锁和 best-effort 后台 executor 不是多实例分布式一致性方案。
- **文档同步**：README、AGENTS、架构/API 文档、项目进度和校招材料已更新到本轮实现，后续代码变化需继续同步维护。
