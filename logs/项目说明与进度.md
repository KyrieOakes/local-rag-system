# 项目说明与进度 — Local RAG System

> **当前快照**：2026-07-31
> **定位**：面向个人/单机知识库的 local-first RAG 全栈项目。LLM 可使用本地或云端 OpenAI-compatible 服务，Embedding 通常使用本地服务。

本文记录“项目现在是什么”和“历史上怎么迭代到这里”。每次变更的详细动机与文件清单见同目录 `DevLog-*.md`；面试复习以仓库根目录的 `校招准备.md` 为准。

---

## 一、当前一句话

用户可以上传或批量扫描 PDF/TXT/Markdown/DOCX，系统通过版本化增量管线把 chunk 写入 Qdrant；查询时先恢复服务端长期记忆并做路由/改写，再执行向量召回、可选 Rerank、统一上下文预算和 LLM 生成，最后通过 JSON 或 SSE 返回回答与来源。

## 二、启动

```bash
conda activate localrag
cp .env.example .env

# Qdrant
docker compose up -d

# Backend
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# Frontend（另一个终端）
cd frontend
npm ci
cp .env.example .env
npm run dev
```

先在 LM Studio/Ollama 或其他服务中加载与 `.env` 中 `LLM_MODEL`、`EMBEDDING_MODEL` 一致的模型。

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/health/ready
```

- `/health`：只表示应用进程存活；
- `/health/ready`：检查 Qdrant、LLM endpoint、Embedding endpoint，未就绪返回 503。

- 完成上传 → 加载 → 分块 → embedding → 检索 → 生成闭环。

### Sprint 2 — 文档管理与前端交互

- React/Vite 聊天 UI；
- 文档列表和删除；
- 多文件上传、逐文件状态；
- assistant Markdown 渲染和中文排版修复。

### Sprint 3 — 查询处理与 UI 重构

- 增加意图识别与查询改写；
- Editorial Ink 深色设计系统；
- 早期版本使用文本行协议，当前已升级为 JSON 结构化路由。

### Sprint 4 — 批量摄取与增量更新

- 增加 `ingest.py`；
- 目录递归扫描、Markdown header-aware 切分；
- SQLite MD5 状态、批量 embedding、500 points/batch Qdrant upsert；
- 上传和 CLI 复用同一管线。

早期策略是“变化后先删旧向量再写新向量”，当前已由 Sprint 8 的版本化写入、原子激活和 durable cleanup queue 替代。

### Sprint 5 — 检索评估体系

- 22 条示例 golden questions；
- Recall@K、Precision@K、MRR、NDCG、context quality；
- CLI 报告和 Notebook 多策略对比。

早期报告存在 Recall 分母语义问题。当前只承认 `metric_semantics_version=evidence-label-v2` 的新报告，历史分数不能直接作为当前结论。

### Sprint 6 — 路由、对话和 SSE

- Layer 0 正则 quick reply；
- Layer 1 LLM 路由、意图、改写或 direct answer；
- `conversation_id` 和客户端历史；
- SSE routing/status/token/sources/error/done；
- 可选 Cross-Encoder / Hybrid Rerank；
- SQLite 会话列表与刷新后恢复。

早期实现的 FIFO-like embedding cache、daemon thread、direct `.split()` 流式和隐式 rerank 分数均已在 Sprint 8 修正。

### Sprint 7 — 服务端长期记忆与统一上下文

- 服务端按 `conversation_id` 恢复 SQLite 历史；
- 滚动摘要 + 最近原文；
- 客户端尾部最长重叠对账；
- system/question/history/documents/output/safety 的统一 token 预算；
- 超大问题同步 413、SSE context error；
- 路由失败 fail-open 到 RAG；
- 完整原文保留，摘要只推进游标。

### Sprint 8 — 面试导向全链路可靠性整改（2026-07-31）

本轮解决“功能看起来存在，但追问实现会露出缺口”的问题：

1. **版本化摄取**
   - 稳定 `document_id`、`version_id`、pipeline fingerprint；
   - 新版本写入后，SQLite 原子激活当前版本并登记旧版清理；
   - 激活失败精确回滚新版，清旧失败则保留新版和 durable retry；
   - 旧 UUID 上传身份归并、同名 legacy 文档可按稳定 path-ID 精确删除；
   - collection 向量维度 fail-fast；
   - 目录消失文件安全对账；
   - PDF/DOCX/UTF-8 内容检查、25 MiB 默认上限。

2. **文档生命周期**
   - 列表返回 `document_id`；
   - 前端优先按 ID 删除；
   - source 兼容只在唯一匹配时生效，同名返回 409；
   - 歧义响应不再暴露本地存储路径。

3. **Rerank 与配置**
   - 明确 `RerankCandidate(document, vector_score)`，不再丢向量分数；
   - Hybrid 支持英文 token 和 CJK bigram；
   - `TOP_K`、candidate top N、final top K 真正接入同步/SSE；
   - Cross-Encoder 默认 `trust_remote_code=false`。

4. **评估可信度**
   - Recall 分母改为完整 golden evidence；
   - Precision 去除重复 evidence 膨胀；
   - MRR/NDCG 保留真实 rank；
   - 报告增加 dataset hash、Git 状态、settings fingerprint；
   - Notebook 修复旧 Rerank API，并拒绝混比旧指标报告。

5. **异步与持久化**
   - SSE 阻塞阶段通过 `asyncio.to_thread`；
   - 取消/失败不保存部分回答；
   - 每阶段稳定 `error + done`；
   - 有界后台 executor 替代每请求 daemon threads；
   - `turn_id` 唯一约束、SQLite busy timeout/条带锁；
   - JSONL 写锁和阶段耗时。

6. **安全与运维**
   - 类型化配置和跨字段校验；
   - 可选 `X-API-Key`、CORS allowlist、请求 ID；
   - `/health/ready`；
   - 错误脱敏和 prompt injection 边界；
   - 依赖版本固定、Qdrant image 固定；
   - GitHub Actions、后端/前端 Dockerfile、full compose profile；
   - 移除远程 Google Fonts 运行时依赖。

7. **验证**
   - 后端 160 项离线测试通过；
   - 前端 `npm run lint` 与 `npm run build` 通过；
   - `git diff --check`、compileall、Compose 配置继续作为交付检查。

## 五、当前核心数据流

### 5.1 版本化摄取

```text
scan/upload
  → 扩展名、大小、内容真实性检查
  → stable document_id
  → MD5 + pipeline fingerprint → version_id
  → load + split + per-file chunk_index
  → batch embedding
  → Qdrant vector-dimension validation
  → upsert new version (wait=true)
  → SQLite atomic active-row update + cleanup enqueue
  → idempotent delete old exact version
  → complete cleanup record
  → cleanup old uploaded UUID file
```

未变化文件跳过。管线指纹包含 embedding endpoint/model/revision、chunk 参数和 splitter version，因此配置变化不会被 MD5 误判为“无需更新”。

### 5.2 查询

```text
request
  → server memory restore + client-tail reconciliation
  → routing context budget
  → Layer 0 quick reply
     or Layer 1 JSON route/intent/rewrite/direct
  → if RAG: vector recall
  → optional Cross-Encoder / Hybrid rerank
  → generation context budget
  → grounded prompt + LLM
  → JSON response or SSE
  → bounded background persistence + summary + trace
```

RAG 默认召回 `TOP_K`。启用 Rerank 时先取 `RERANKER_CANDIDATE_TOP_N`，再保留 `RERANKER_FINAL_TOP_K`。

### 5.3 上下文

```text
input_limit
= LLM_CONTEXT_WINDOW
- LLM_RESERVED_OUTPUT_TOKENS
- CONTEXT_SAFETY_MARGIN_TOKENS
```

服务端按优先级保留：当前问题（不截断）→ 滚动摘要 → 最新完整消息 → 排名靠前文档。最后一条超长历史或最后一个文档块可以保留头尾后截断。

### 5.4 SSE

```text
正常: routing → status* → token* → sources → done
失败: [routing] → [status*] → error → done
取消: CancelledError 向上传播，不持久化
```

direct answer 按 Unicode 字符切片，保留中文、换行与连续空格。

## 六、评估

```bash
conda activate localrag
python evaluation/run_retrieval_eval.py \
  --dataset evaluation/datasets/golden_retrieval.example.jsonl \
  --top-k 5 \
  --experiment-name vector-baseline
```

可选：

```bash
--use-query-processor
--use-reranker --reranker-type cross_encoder --rerank-top-n 20
```

当前语义：

- Recall = 命中唯一 evidence / 全部 golden evidence；
- Precision = 前 K 槽位中新 evidence 槽位 / K；
- MRR = 首个相关结果真实 rank 的倒数；
- NDCG = 保留噪声/重复占据的 rank，并支持分级 relevance；
- context quality = chunk 层无关率、重复率、综合冗余。

旧报告若没有 `metric_semantics_version: evidence-label-v2`，只作为历史产物，不再参与当前策略结论。

Notebook 的 LIVE 模式会真实执行并记录 Rerank 状态；DEMO 模式使用稳定 SHA-256 种子并明确禁用 Rerank。主指标只计算前 `TOP_K`，额外召回只用于敏感度分析；多实验比较还会拒绝 dataset、mode、top-k 或 pipeline fingerprint 不一致的报告。

## 九、当前边界

- 单用户/单节点，不含 JWT、多租户、RBAC、限流、配额；
- 可选 API Key 只是简单内网保护；
- SQLite 不适合多实例共享写；
- 文档列表通过 Qdrant scroll 聚合，规模大后需独立 catalog；
- 只有 dense vector recall，Hybrid 是后置融合而非 BM25+dense 双路召回；
- 无 OCR、多模态、表格结构恢复、跨文档语义去重；
- 离线 tokenizer 是保守近似；
- rolling summary 尚无事实保持评估；
- JSONL 和阶段耗时尚未接 Prometheus/OpenTelemetry；
- 前端仍集中在大型 `App.jsx`。

这些是当前工程取舍，不应在面试中包装成已实现的企业级能力。
